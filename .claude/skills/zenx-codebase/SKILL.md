# ZenX codebase map

ZenX = Zen Browser + our additions, merged with upstream Zen every day.
Zen = Firefox + patches + its own UI code. Firefox source is **not** in git.

## The one thing to understand first: src/ vs engine/

| Path | In git? | What it is |
|---|---|---|
| `engine/` | no (gitignored) | Full Firefox source tree (~5 GB) with Zen applied. Generated by `npm run download` + `npm run import`. Has its own git repo used only to diff patches. |
| `src/**/*.patch` | yes | Diffs against Firefox files. `src/browser/foo/Bar-sys-mjs.patch` patches `engine/browser/foo/Bar.sys.mjs`. |
| `src/**` (non-patch files) | yes | Whole files copied/**symlinked** into the same path under `engine/` by `surfer import`. E.g. `src/zen/` → `engine/zen/`, `src/zenx/` → `engine/zenx/`. |
| `prefs/**/*.yaml` | yes | Default prefs, compiled into Firefox prefs by `tools/ffprefs` during `npm run import`. |
| `locales/<lang>/browser/browser/zen*.ftl` | yes | Fluent strings. en-US is copied into `engine/browser/locales/en-US/browser/` by `python3 scripts/update_en_US_packs.py`. |
| `surfer.json` | yes | Firefox version Zen builds on, brand config. |

Consequences:
- Edit **whole files** in `src/` (the engine copy is a symlink, so the edit is live there too).
- Never hand-edit a `.patch`. Edit the real file in `engine/`, then `npx surfer export <path relative to engine>` to regenerate the patch in `src/`.
- Editing a Firefox file in `engine/` without exporting = the change is lost on the next import.
- If `engine/` is missing or stale, see the `zenx-build` skill.

## Where things are

- `src/zen/` — Zen's own UI, one folder per feature: `spaces/` (workspaces: `ZenSpaceManager.mjs` = `gZenWorkspaces`), `sessionstore/` (spaces + tabs persistence in `zen-sessions.jsonlz4`, `ZenWindowSync`), `tabs/` (`gZenPinnedTabManager`, essentials), `folders/`, `split-view/`, `glance/`, `compact-mode/`, `share/` (space export/import, `gZenShareManager`), `space-routing/`, `sync/` (Firefox Sync of spaces), `welcome/`, `common/` (startup, `ZenPreloadedScripts.js`, `zen-sets.js` command switch), `tests/`.
- `src/zenx/` — **ZenX additions** (see `docs/zenx.md`): `ZenXProfileSpaces.sys.mjs` (spaces bound to Firefox profiles, process-wide), `ZenXProfileSpacesUI.mjs` (window UI), `arc/` (Arc importer), `tests/`.
- `src/browser/base/content/zen-*.inc.xhtml` — Zen markup included into `browser.xhtml` (popups, commands, sidebar).
- `prefs/zen/*.yaml`, `prefs/zenx/*.yaml` — feature prefs; `prefs/firefox/*.yaml` — overrides of Firefox defaults.
- `.github/workflows/zenx-sync-upstream.yml` — daily upstream merge (see `zenx-upstream-sync` skill).
- `docs/zenx.md` — ZenX docs, including **the table of every Zen file ZenX modifies**. Keep it current.

## How code gets into a browser window

1. `src/zen/moz.build` lists folders in `DIRS` (ZenX: `"../zenx"`). Modules are declared with `EXTRA_JS_MODULES.<path> += [...]` and served under `resource:///modules/<path>/`: Zen uses `EXTRA_JS_MODULES.zen` → `resource:///modules/zen/X`; ZenX uses `EXTRA_JS_MODULES.zenx` → `resource:///modules/zenx/X`, and a subfolder is `EXTRA_JS_MODULES.zenx.arc += ["arc/X.sys.mjs"]` → `resource:///modules/zenx/arc/X.sys.mjs` (all in `src/zenx/moz.build`). CSS/SVG go through `jar.mn`/`jar.inc.mn` → `chrome://browser/content/...`.
2. `src/zen/common/ZenPreloadedScripts.js` imports per-window modules with `ChromeUtils.importESModule(url, { global: "current" })`. Such `.mjs` modules run *in the window global*: they use `window`, `document`, `gBrowser`, `gZenWorkspaces` directly and publish themselves as `window.gZenSomething = new ...`.
3. Process-wide singletons are `.sys.mjs` (one instance for all windows), imported where needed, sometimes registered via `*Components.manifest` categories.
4. New globals must be added to `src/zen/zen.globals.mjs` for lint.

Window lifecycle: `gZenWorkspaces.init()` runs from `ZenStartup.mjs`; anything that needs spaces should `await gZenWorkspaces.promiseInitialized`. Useful events: `ZenWorkspaceDataChanged` (space list/data changed), `ZenWorkspacesUIUpdate` (switcher re-rendered). `gZenWorkspaces.addChangeListeners(fn)` runs on space switch.

## Key APIs you'll reuse

- Spaces: `gZenWorkspaces.getWorkspaces()`, `getWorkspaceFromId(uuid)`, `createAndSaveWorkspace(name, icon, dontChange, containerTabId, {beforeChangeCallback})`, `saveWorkspace(obj)` (extra fields on the object persist in the session store), `removeWorkspace(uuid)` (closes its tabs), `changeWorkspaceWithID(uuid)`, `moveTabsToWorkspace(tabs, uuid)`, `workspaceElement(uuid).pinnedTabsContainer/.tabsContainer`, `activeWorkspace`, `privateWindowOrDisabled`.
- A space as data (tabs/folders/split views): `gZenShareManager.importSpace(item)` with the schema in `src/zen/share/share.schema.json`; ZenX serializer: `ZenXProfileSpaces.serializeSpace(window, uuid)`.
- Essentials: `gZenPinnedTabManager.addToEssentials(tab)`; folders: `gZenFolders.createFolder(...)`; split: `gZenViewSplitter.splitTabs(tabs, "grid")`.
- Firefox profiles: `SelectableProfileService` (`resource:///modules/profiles/SelectableProfileService.sys.mjs`) - every profile is a separate process; cross-profile data goes through shared prefs (`trackPref`).
- Command line: `--space <uuid|name>` switches/opens a space (`BrowserContentHandler-sys-mjs.patch`).

## Strings and prefs

- Strings: add to `locales/en-US/browser/browser/<file>.ftl` (file name must start with `zen`, ZenX uses `zenx-*.ftl`), load in JS with `document.l10n.addResourceIds(["browser/<file>.ftl"])` or in markup via `zen-locales.inc.xhtml`. Add `locales/pl/...` too if you can. "Profile" in Zen's existing UI strings means **container**, not Firefox profile.
- Prefs: add `- name: ... / value: ...` entries to a yaml in `prefs/`. Don't define the same pref in two yaml files (order is not deterministic) - edit the existing entry instead.

## Agent docs inside engine/

`engine/CLAUDE.md` and `engine/AGENTS.md` are **Firefox's** agent docs (for mozilla-central). They are useful for Firefox internals but their workflow (hg, phabricator, `./mach` from the root) is not ours - for repo workflow follow this repo's `CLAUDE.md` and skills.

## Searching

`engine/` is huge; scope searches. Zen/ZenX code: `grep -rn X src/zen src/zenx`. Firefox code: `grep -rn X engine/browser/components/<area>` or use https://searchfox.org (mozilla-central, close to our Firefox version in `surfer.json`). Which Firefox files Zen patches: `ls src/<path>` for `*.patch`.
